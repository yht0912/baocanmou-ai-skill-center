# 技能治理规范

## 新增前

- 记录原始 URL、许可证、确切版本或 Git 提交号。
- 阅读完整 `SKILL.md`，再按它的路由阅读必需引用文件。
- 检查脚本、二进制、安装钩子、网络请求、敏感路径和外部写入。
- 先与现有技能做名称、描述、触发条件和运行能力对比。
- 如果只是不同风格或重复包装，优先扩展已有技能，不新建重复项。

## 安装后

- 运行结构验证器，确认 frontmatter、资源链接和目录结构。
- 在需要的真实运行时中做最小调用，不只做文本检查。
- 验证各 AI 入口与中心源的解析路径和断链数。
- 对可执行产物记录版本、文件数与 SHA-256，不将敏感信息写入证据。

## 升级与回滚

1. 升级前先记录当前提交号、版本、目录哈希和真实最小调用结果。
2. 将原目录备份到带时间戳的隔离位置，不覆盖唯一可用版本。
3. 核对上游变更和新增依赖，再替换中心源。
4. 重跑结构、链接、依赖、网络模式和真实调用验证。
5. 失败则恢复原目录，并用原提交号、哈希和调用结果复验。

## 最小交付证据

- 中心源目录和技能名。
- 来源 URL、许可证、版本或 Git 提交号。
- 目标 AI 入口及其解析目标。
- 结构验证、真实最小调用和断链检查结果。
- 有问题时的回滚位置和未完成层级。
