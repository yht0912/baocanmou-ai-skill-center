# 技能中文解释与视觉预览

## 为什么不直接改第三方文件

批量改写第三方 `SKILL.md` 会破坏更新、哈希和来源真实性。包参谋把中文解释放在独立显示层：英文 ID 和原始文档保持不变，中文名称与说明单独生成并允许校正。

自定义内容写入：

```text
~/.baocanmou/skill-center/translations.json
```

该文件只保存在本机，不进入公开仓库。

## 每个技能的解释结构

1. 中文名称：根据本地中文字段、包参谋词典或类别规则生成。
2. 英文原名：保留兼容和检索。
3. 主要用途：回答“这个技能用来做什么”。
4. 能力特点：回答“它与其他技能有什么差别、执行时要注意什么”。
5. 英文原文：可回到 `SKILL.md` 检查真实触发条件和依赖。

自动生成内容属于导航性解释，不替代人工翻译。用户可在详情页校正中文名称与说明。

## 信息优先与截图规则

技能卡不生成装饰性大图，第一视觉层固定展示：

1. 中文名称与英文 ID；
2. 一句话“主要用途”；
3. 最多 3 条能力特点；
4. 方策分、风险和连接状态。

图像生成类技能可从“图像生成”分类直接筛选。卡片会显示技能目录内实际可用的“可视案例”数量，搜索也同时覆盖主要用途与能力特点。

真实案例只作为详情页补充，每个技能最多同时展示 4 张，读取优先级为：

1. 文件名含 `screenshot` 或 `preview` 的本地图片；
2. 文件名含 `cover` 或 `example` 的本地图片；
3. 位于 `examples` / `showcase` / `samples` / `gallery` 目录的本地图片；
4. 其他合规本地图片。

不读取 App 图标、依赖包、构建产物或超过 4 MB 的图片。开发者实际附带的案例少于 3 张时，界面会明示“案例不足”；没有真实图片时不制造“效果截图”，不拿其他技能的图片或通用占位图补数。
