# 包参谋热门技能榜单方法

> 包参谋 · [www.bcmsj.com](https://www.bcmsj.com) · 开源交流学习使用

## 目的

热门技能榜单是一个“发现底座”，帮助用户先看到当前使用量高、社区关注度高、仍在维护且更契合包参谋工作方向的 AI Skills。它不是照抄 GitHub 热门榜，也不是自动安装清单、安全认证、质量保证或官方背书。

## 公开数据源

- **技能安装量与近期安装趋势**：[skills.sh](https://skills.sh/) 公开榜单。skills.sh 将其命令行工具产生的匿名安装遥测用于排行榜。
- **仓库星标、分叉、更新时间、许可证标识、描述和主题**：[GitHub REST API](https://docs.github.com/en/rest/repos/repos) 的公开仓库元数据。
- **官方标识**：skills.sh 公开数据中的 `isOfficial` 字段，仅说明该来源被标识为官方，不代表包参谋完成了安全审计。

## 为什么不能直接使用“下载量 + 评分”

GitHub 没有统一的单个 Skill 下载量或用户评分字段。GitHub Release 的 `download_count` 只统计发布附件，Stars 也只是仓库关注度，不是用户评分。因此榜单并列展示两类分数：

- **综合热度分**：尽量客观地反映公开采用度和社区信号。
- **包参谋推荐分**：在公开信号之上加入维护、许可清晰度、资料完整度和包参谋能力方向判断。

包参谋推荐分是本项目的透明编辑判断，不冒充 GitHub 官方评分，也不把无法验证的信息写成事实。

## 综合热度分 v1

先对数归一化各项规模指标，再按以下权重计算 0–100 分：

| 信号 | 权重 | 说明 |
| --- | ---: | --- |
| 累计安装量 | 55% | skills.sh 的单个技能累计安装次数 |
| 近期安装量 | 20% | skills.sh 公布的近期安装序列之和 |
| GitHub 星标 | 12% | 来源仓库关注度 |
| GitHub 分叉 | 5% | 来源仓库参与度 |
| 仓库活跃度 | 5% | 最近推送时间，超过两年逐步降至 0 |
| 官方标识 | 3% | skills.sh 的官方来源标识 |

## 包参谋推荐分 v2

推荐分同样采用 0–100 分，权重如下：

推荐等级按分数分为 A（85 分及以上）、B（75–84.9 分）和 C（75 分以下），用于快速浏览，不代替安装前审查。

| 信号 | 权重 | 包参谋判断 |
| --- | ---: | --- |
| 累计安装量 | 30% | 已被真实采用，但避免“只看历史体量” |
| 近期安装量 | 20% | 发现正在增长的新技能 |
| GitHub 星标 | 10% | 社区关注度，因是仓库级信号而降低权重 |
| GitHub 分叉 | 4% | 社区参与度，同样只作辅助 |
| 仓库活跃度 | 12% | 最近两年持续衰减，长期停更会降权 |
| 官方标识 | 4% | 来源可信度辅助信号，不等于安全审计 |
| 许可证清晰度 | 8% | 仅判断仓库是否提供可识别 SPDX 标识，不判断许可一定适合商业使用 |
| 资料完整度 | 4% | 仓库描述与主题是否完整，不代表 Skill 文档质量已人工验收 |
| 包参谋方向契合度 | 8% | 优先设计、PPT、视频、营销、内容、数据可视化、浏览器自动化等实际工作能力 |

最终按包参谋推荐分排序，再按累计安装量和名称稳定排序。为避免同一仓库共享 Stars、Forks 后垄断榜单，每个仓库最多入选 20 个 Skill；已归档或停用的仓库直接排除。

每个入榜项同时生成最多四条中文/英文入选理由，例如“累计安装量高”“近期增长快”“持续维护”“许可证明确”。许可证缺失、长期停更或仓库资料不足会被写入审查标记，但不会被包装成已经完成代码安全审计。

## 定期更新机制

- GitHub Actions 每周一、周四北京时间 08:10 自动复筛。
- 每次先运行算法测试，再抓取公开数据并验证 300 条结果的结构和连续排名。
- 只有排名或元数据发生实质变化时才提交，避免仅因时间戳变化制造无效提交。
- 自动生成中英文观察摘要，记录前 30 名、排名变化、推荐分和入选理由。
- 榜单更新不会自动安装到 Codex、Claude 或其他 AI 软件；安装仍需用户选择，并遵循来源、依赖、权限和可回滚审查。

## 边界与安全

- 流行不等于安全，也不等于适合你的工作流。
- 榜单不会自动安装任何技能；用户应先查看来源和 `SKILL.md`，再手动选择安装。
- 仓库级星标和分叉会被同仓库中的多个技能共享，因此它们仅作为辅助信号。
- 仓库级许可证、描述、主题和更新时间也会被同仓库中的多个技能共享，不能替代对单个 `SKILL.md` 的检查。
- 数据源结构变化、API 限额或仓库删除可能造成短期缺失；生成器遇到不完整榜单时会拒绝覆盖已有快照。
- 安装第三方技能前，建议检查依赖、脚本、网络请求、写入范围和许可证。

## 可复现

```bash
npm run test:featured
node scripts/fetch-featured-skills.mjs
```

算法、权重、数据时间和来源都会写入根目录的 `featured-skills.json`，便于审计和复算。
