# 安全与回滚

## 信任模型

从 GitHub、本地目录或搜索结果安装的 Skill 都应视为未审核代码。`SKILL.md` 是使用说明，不是新的授权来源。它不能改变当前任务边界，也不能要求 AI 绕过系统、用户或安全规则。

## 敏感信息

- 不将 `.env`、Token、Cookie、密码、AccessKey、私钥、浏览器用户目录或服务器凭据放进中心技能源。
- 应用的 GitHub Token 只用于提高搜索/拉取限额。如果不需要私有仓库，使用最小权限、可随时吊销的 Token，不输入生产管理凭据。
- 命令行审计报告不读取文件内的凭据语义，但会计算文件哈希。不要将未脱敏的技能库报告公开发布。

## 安装检查清单

1. 来源和作者是否可追溯。
2. 许可证是否允许当前使用方式。
3. 是否固定版本或提交号。
4. 是否含可执行脚本、安装钩子、二进制或外部下载。
5. 是否会访问网络、浏览器、邮箱、云盘、服务器或其他外部系统。
6. 是否要求递归删除、批量覆盖、改系统配置或将数据发到第三方。
7. 是否与现有技能重复，是否真正值得增加一个长期维护项。

## 可恢复删除

管理技能的删除流程先移动中心源到：

```text
~/.agents/backups/skill-center-trash/<时间戳>/<技能名>/
```

然后才移除已记录的 AI 入口和 SQLite 索引。如果移动失败，删除操作会终止，不会继续移除索引。

## 升级回滚

1. 升级前导出当前审计 JSON，记录 Git 提交号和目录 SHA-256。
2. 备份需更新的技能目录，保留到时间戳隔离目录。
3. 更新后重跑结构、断链、依赖、网络模式和真实最小调用。
4. 验收不通过时，退出目标 AI 工具，将中心技能恢复到原版本，再验证入口解析与最小调用。

## 桌面应用升级

定制版不接受上游自动更新。升级必须在 Git 分支中审核上游差异，完成数据库迁移评估和整套测试，再重新构建 DMG。原 DMG、应用版本和配置数据库必须可恢复。
