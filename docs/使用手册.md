# 使用手册

## 首次启动

1. 确认 `~/.agents/skills` 是当前真实共享技能源，不要先手工移动任何技能。
2. 启动「包参谋 AI 技能中心」。应用会创建自己的 SQLite 索引，但不会复制或重命名中心技能。
3. 在「我的技能」中确认已有技能数量与中心源大致一致。
4. 在「工具管理」中只启用本机真正使用的 AI 工具。
5. 运行一次只读审计，确认断链数和链接指向。

## 界面怎么用

- 「已托管能力」是首页，数字表示本机已经登记和治理的技能；「热门技能库」显示在线发现目录数量，默认 300 条。两者不会相加，也不会把在线条目冒充为已安装技能。顶部显示当前技能和工具数量，搜索框可按中文译名、英文原名、用途或来源查找。
- 左侧「引入新能力」用于从 Git 仓库或本地文件夹添加技能；「能力归档、工具编组、版本与风险」用于日常治理。
- 默认使用清单视图：每行保留中文名、英文 ID、范围、工具编组摘要和启停开关。需要逐个调整 AI 工具时，切到卡片视图或点技能名称进入详情。
- 墨黑底、米白框架和黄色决策点组成“方策”图标；桌面、Dock 与应用侧栏使用同一标志。
- 最小支持窗口为 `900 × 640`；窗口变窄时会自动隐藏次要路径、时间和低频按钮，不影响搜索与启停。

## 中英双语浏览

- 英文技能在列表中以“中文译名＋英文原名”两行显示。
- 搜索框同时支持中文名、英文名、用途和来源。
- 切换为“按名称”排序时，按中文主名排序。
- 界面不会改名英文目录或改写技能指令；这是为了保持 Codex、Claude 和其他 AI 工具的兼容性。

## 安装技能

桌面端支持 Git URL 和本地文件夹。安装前先确认：

- 它填补的能力不是已有 Skill 的重复包装。
- 它有可理解的许可证和可追溯版本。
- `SKILL.md` 中声明的脚本、依赖和网络请求符合当前任务边界。
- 不安装保含 Token、Cookie、密码、私钥或浏览器资料的文件夹。

选择全局同步时，技能会被连接到目标 AI 的全局技能目录；选择项目级时，它会连接到指定项目的对应目录。两者的技能本体始终保留在中心源。

## 更新技能

- Git 来源和可追溯的本地来源可以在应用内检查更新。
- 由旧系统登记的 `existing` 技能没有可靠来源时，更新按钮会禁用，防止猜测来源。
- 自动更新是技能源更新，不是桌面应用自更新。桌面应用本身的上游自更新已禁用。
- 对高风险 Skill，应手工固定提交并在升级后做真实最小调用。

## 删除与恢复

应用中删除管理技能时，系统会：

1. 先将中心技能移入 `~/.agents/backups/skill-center-trash/<毫秒时间戳>/<技能名>/`。
2. 移除本地数据库中记录的 AI 入口。
3. 删除索引记录。

要恢复时，先退出应用，把隔离目录放回 `~/.agents/skills/<技能名>`，再重新启动。首次登记逻辑会重新识别它。

## 命令行审计

```bash
python3 tools/skill_center_audit.py
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--central <path>` | 审计非默认中心技能源 |
| `--home <path>` | 使用其他用户根目录做测试或远程盘点 |
| `--format json` | 输出结构化证据 |
| `--output <path>` | 写入指定报告文件 |
| `--strict` | 发现问题时以退出码 2 结束 |

## 故障排查

- **某个技能不显示**：检查该目录是否有 UTF-8 编码的 `SKILL.md`。
- **目标 AI 不识别**：检查入口路径、断链和该 AI 对 Skill 规范的真实支持，不只看文件是否存在。
- **同步目标已存在**：先比对现有目录与中心源，不直接覆盖用户文件。
- **更新不可用**：表示当前技能没有可追溯 Git/本地来源，先补齐来源证据。
- **同步后仍无法调用**：重启目标 AI 软件，再核对它的当前版本、检出路径、运行时依赖和网络模式。
