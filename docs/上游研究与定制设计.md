# 上游研究与定制设计

## 研究对象

本次以 [qufei1993/skills-hub](https://github.com/qufei1993/skills-hub) 为学习基线，固定在提交 `9d9f490f8ae0a3f91d714867cffe3927ada6e8ae`，对应上游 0.9.1。研究不只阅读 README，还逐层检查了 React 界面、Tauri 命令层、Rust 核心模块、SQLite 数据模型、安装器、同步引擎、适配器、发现与导入、Git 更新及系统调度。

上游未修改基线已执行 `npm run check`，通过前端 48 项测试和 Rust 146 项测试，用于证明定制起点是可构建的。

## 上游核心模型

```text
Git / 本地文件夹 / 在线搜索
               ↓
        安装进中心技能库
               ↓
      SQLite 记录来源、标签、目标
               ↓
     软链接 / 目录联接 / 副本
               ↓
      全局或项目级 AI 技能入口
```

关键优点：

- 技能只安装一次，再同步到多个 AI 工具。
- 内置适配器把不同工具的全局与项目级路径封装起来。
- Git 和本地来源技能可以检测、更新和定时运行。
- 标签、启用状态、扫描源与同步目标独立，适合大量 Skill 治理。
- Rust 核心逻辑可独立测试，Tauri 层只负责 IPC 和桌面能力。

## 不能直接照搬的边界

| 上游默认 | 当前工作台的风险 | 定制决策 |
|---|---|---|
| 中心库为 `~/.skillshub` | 会与已有 `~/.agents/skills` 形成双重事实 | 中心源改为 `~/.agents/skills` |
| 首次使用以从工具目录导入为主 | 已有中心源与大量软链接，复制导入会冲突 | 自动登记现有中心技能并调和现有链接 |
| 上游桌面端自更新 | 可能把个人定制覆盖回官方版 | 禁用自更新，只手工审核上游更新 |
| 删除后移除中心文件 | 维护中的个人 Skill 难恢复 | 改为时间戳隔离回收 |
| 中英切换 | 对个人工作台增加翻译维护成本 | 界面固定简体中文 |
| 无 ZCode 适配器 | 当前本机已有 `.zcode/skills` | 增加 ZCode 全局与项目级适配 |
| 应用内的状态即主要证据 | 不足以证明真实目录、断链和哈希 | 增加独立只读审计器与治理 Skill |

## 定制版产品原则

1. **一个事实源**：技能本体只在 `~/.agents/skills` 维护。
2. **现有资产优先**：首次启动先登记和识别，不抢占、不覆盖。
3. **可恢复**：删除、升级和重构必须有隔离或备份路径。
4. **来源透明**：安装和更新前核对 URL、许可证、提交号、依赖与网络边界。
5. **真实验收**：应用状态、链接存在、单元测试与真实最小调用分层验证。
6. **不为数量扩张**：先做能力地图和重复审计，再安装真正缺失的技能。

## 上游跟进方式

上游作为 Git 历史保留。升级时必须先查看新版变更和数据库迁移，再将指定提交合并到 `baocanmou-cn` 分支；禁止在不评审差异的情况下直接用上游发布包覆盖定制版。
